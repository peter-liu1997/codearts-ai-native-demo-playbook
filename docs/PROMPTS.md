# 码道演示提示词卡

以下提示词根据附件案例重写，保留业务目标和验收标准，便于现场在码道中重新生成或修改案例。建议先运行仓库成品建立基线，再用提示词展示“从意图到制品”的过程。

## 01 用户分组

> 为 `UserGroupingUtil` 续写方法：输入用户列表，过滤空对象、空年龄和负年龄，按年龄分组；空输入或无有效用户时返回空 Map，不返回 null。补充最小测试。

## 02 库存重构

> 先解释 `calculateCategoryInventory` 的业务逻辑和质量问题；在不改变行为的前提下消除深层嵌套与重复 Map 查询。验证通过后，再给出等价 Java Stream 实现，保持空值处理不变。

## 03 商品管理项目

> 生成一个 Java 商品管理后端，采用 controller/service/model/repository 分层，内存存储，统一 JSON 响应；支持列表、按 ID 查询、新增、修改和删除。提供启动方式、接口示例与自动化测试。

## 04 控制器测试

> 为 `ProductController` 设计轻量测试：隔离 Service，覆盖查询所有、按 ID 成功/失败、新增、修改、删除；生成后执行测试，读取失败日志并自动修正，直到全绿。

## 05 代码库问答

> 建立当前仓库索引后，解释 `ProductService.createProduct` 的真实调用链，并列出引用到的类、方法和文件。若仓库不存在某个符号，明确回答未找到，不要推测。

## 06 认证超时

> 针对 `src/auth/oauth.py` 的 refresh token 超时问题调用 Debug 技能。参考上一轮 `EXPIRY_DELTA` 从 30 改为 60 的历史，沿 `jwt.decode → redis.get` 调用链检查，并按我的偏好使用 pdb。先给排查计划，再执行。

## 07 会议室原型

> 根据会议室预约草图生成单页 HTML/CSS/JS：城市联动楼宇，高级搜索按人数和类型筛选，左侧 6 个会议室，右侧按半小时选择日期和连续时段，确认弹窗；浅蓝白配色、响应式、无外部库。

## 08 OpenAI Mock

> 用 Python 实现本地 OpenAI 兼容 `/v1/chat/completions`，解析 messages/model/tools/tool_choice。第一次根据 tools 返回标准 tool_calls，tool 结果回传后返回 stop 文本。补 CORS、SSE 流式接口、客户端闭环测试和真实模型适配器接口。

## 09 SaaS 看板

> 严格使用仓库设计 tokens 生成 B2B SaaS 产品分析页：5 个指标卡、用户/会话/收入双轴趋势、留存基准线、功能排行和占比。支持时间筛选、卡片选中、表格悬停、默认折叠明细与昨日/今日对比。除指定区域外不要改动其他样式。

## 10 TCP 扫描

> 读取 `cloud_assets_scan.csv` 的 `ip_address` 和 `port`，用 Python 标准库并发测试 TCP 连通性。必须有超时、受控并发、状态与耗时、错误隔离、CSV/JSON 结果；只扫描清单内目标，并提供本地开闭端口测试。

## 11 API Hub（六轮）

1. 生成纯 HTML/CSS/JS 的 API 文档骨架和用户/订单示例接口。
2. 增加 Key/Value 调试面板、Mock 状态码与 50-300ms 响应时间。
3. 增加 Mock 地址、复制、JSON 编辑与格式校验。
4. 增加方法颜色、Loading、搜索、响应式目录和深色主题。
5. 增加 localStorage、配置导入导出。
6. 审查 XSS，使用安全文本渲染；补 JSDoc、CSS 变量和项目说明。

## 12 电商全栈

> 以最小化变更分六阶段把商品/购物车原型演进为全栈：每阶段只解决一个核心问题；后端需保证库存原子扣减、失败不部分提交、订单确认；每阶段执行计划确认、结构验收、规范审查、代码质量、修复验证和部署检查。

## 13 日志转换 SDD

> 使用规范开发模式实现日志到 Chrome Tracing JSON 的转换。先用 EARS 定义正常、事件、状态、异常和可选行为；确认 spec 后再生成 design/tasks；实现时跳过非法行并记录原因，补齐自动化测试，最终生成可导入的 JSON。

## 14 SMN 插件 SDD

> 为现有 DolphinScheduler 告警框架新增独立 SMN 插件：基于华为云 SDK 和 AK/SK 适配器，进入告警实例、Test Send 与真实告警流程；两种发送复用同一链路；凭据不得硬编码；先索引既有插件扩展点，再按 Spec/Design/Tasks 实施。

## 15 IAM OIDC SDD

> 依据 OpenAPI 契约实现 OIDC 信任委托控制面：HTTPS Issuer、Client ID、自动/手工证书指纹、出站主机白名单、短期凭证。设计需覆盖 SSRF、错误 Client ID、非法 Token 和诊断但不泄密的错误响应；先评审规范与信任边界再编码。

## 16 智能体门户

> 从口述需求收敛企业 AI 智能体门户：卡片/列表、标签筛选、草稿/发布/下线状态机、竞赛生命周期、在线评分与 RBAC。先输出需求与设计文档，确认状态转换和权限矩阵后再生成前后端，并用对话修正边界场景。

## 17 设备内存 SDD

> 在存量 C 工程增量优化管理面内存统计：仅主进程可查询；总量含固定底噪和活动进程上报；重复上报覆盖、退出删除；可靠发送 1 秒一次最多 300 次。先读取全局 DESIGN 和领域 API，拆分设计、编码、编译、测试阶段，C11 严格编译通过。

## 18 鸿蒙电商

> 在 DevEco 初始化工程中生成 ArkTS 电商首页，使用声明式 ArkUI、强类型模型、`@State` 购物车状态，保留 HarmonyOS 配置。先检查现有工程和 SDK 版本，生成后执行静态检查、编译、单元测试，再通过 HDC 隧道在已授权云手机验证。

## 19 成熟度诊断

> 输入 AI 生成代码率、技术性返工率和规范违反率，联合判断工具观望、生成膨胀、规范内耗或进化成熟阶段；输出主要风险、首要动作和趋势监控建议。指标只用于组织改进，不用于个人绩效。

## 20 净 ROI

> 实现 AI 编程 ROI 计算器：NEC=生成率×(1-返工率)×(1-规范违反率)，净 ROI=(毛收益×NEC-全口径成本)/全口径成本。允许调整指标做情景模拟，成本必须包含工具、基础设施、集成、审查、返工、合规和技术债务。
