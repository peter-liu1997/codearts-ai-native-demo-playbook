# 案例 02：库存统计解释、优化与重构

[返回 20 案例截图索引](../UI-IDE-CASE-SCREENSHOTS.md)

## 项目背景

- 业务场景：库存服务需要按分类统计可售库存，并逐步把历史命令式实现改造成更易读、易维护的写法。
- 原始痛点：直接重写容易改变 `null`、空集合和非法库存值的兼容语义，也难向评审者证明重构前后等价。
- 演示目标与边界：先解释现有逻辑，再做局部优化，最后给出等价的 Stream 重构；不引入新框架或业务规则。

## 本案例使用的码道能力

| 维度 | 内容 |
|---|---|
| 工作模式 | 探索模式（Vibe-Coding），适合“理解—优化—重构”的渐进式协作。 |
| 关键上下文 | `#File java/InventoryRefactorDemo.java`、`#Symbol calculateCategoryInventory`。 |
| 智能工程动作 | 基于符号解释代码，识别深层嵌套和重复查找，再生成语义等价的 Stream 实现。 |
| 验证与治理 | 保留原有空值兼容策略，同时运行两种实现并比较结果，再执行案例 02 独立验收。 |
| 客户价值 | 展示码道支持低风险、可解释、可验证的渐进式重构，而不是一次性替换历史代码。 |
